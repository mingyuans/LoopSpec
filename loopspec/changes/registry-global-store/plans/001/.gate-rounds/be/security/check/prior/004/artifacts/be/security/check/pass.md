## 审查结论

- 路径：存储根从最深已存在祖先起逐级 O_NOFOLLOW 打开后才创建（`_private_dir`），路径中任何符号链接都报 `unsafe_path`，且符号链接后不会创建目录；目录 0700、属主与组/其他写权限检查；快照读写全部走目录 fd 与 O_NOFOLLOW。
- 完整性：只在有可信文件表时物化；发布为临时目录 + 原子 rename；已存在快照完整校验、不自动替换；每次读取逐文件按 lock hash 校验。
- 供应链：lock 带 tag 时，冷缓存拉取与已缓存快照都校验 tag→commit 绑定（manifest 记录发布时已验证的 tag）；`config.yaml` 固定 tag 时 lock 必须同 tag，防止省略 tag 绕过。
- 不可信输入：lock 用有界 `parse_yaml`（拒绝别名、重复键、超深嵌套），计划 JSON 捕获 `RecursionError`；lock、计划、manifest 文件表条目与路径都经正则校验；错误信息只回显已校验的定义名与路径。
- git 子进程沿用既有加固（协议白名单、禁用 hooks、fsck、清理 GIT_* 环境、凭据脱敏），工作仓库每次新建于私有临时目录。
- LLM E2E 守卫：`registry` 及任何会读取定义的命令只允许访问测试注入的 fixture registry（用被测 CLI 自己的解析器、检查默认 home 与所有 `--home` 候选），存储必须在项目内。
