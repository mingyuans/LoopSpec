## 审查结论

- 路径：`source_id()` 的可读前缀只含 `[a-z0-9-]`，最长 48 字符，空时回退 `registry`，后接 8 位十六进制；不可能出现 `.`、`..`、`/` 或控制字符，仍经 `_private_dir` 的 O_NOFOLLOW 与属主/权限检查。
- 碰撞：8 位 hash 可被有意构造碰撞。快照 manifest 校验 `url`、`path`、`commit` 与全部文件 hash，碰撞来源只会得到 `registry_store_corrupt`，不会读到对方内容；`tags/<tag>` 记录现在包含 `url`、`path`、`tag`、`commit` 并按完全相等比较，碰撞来源不能借用对方已验证的 tag 绑定（有回归用例）。
- 前几轮修复点（符号链接、tag→commit 绑定、固定 tag、有界解析、LLM 守卫 fixture 限制）未受影响。

## 剩余风险

- 碰撞的两个来源会共用同一目录，后到者在读取时报错，需要改 `url`/`path` 写法或清理目录（拒绝服务，非内容替换）。
- 既有剩余风险不变：读命令隐式联网（已接受设计）、git 浅拉取无磁盘配额（既有）、用户 home 祖先目录可被他人重命名时的竞态（威胁模型一致）。
