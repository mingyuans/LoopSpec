## ADDED Requirements

### Requirement: 可搜索多选工具选择器
交互式工具选择 SHALL 以多选列表形式呈现，支持以下操作：上下方向键在候选项间移动；空格键切换当前项的勾选状态；直接输入字符按显示名过滤候选项；回车确认并返回全部已勾选项。选择器 SHALL 在提示行中说明可用键位，并 SHALL 显示可用工具总数。候选项数量超过一屏时 SHALL 分页呈现并指示当前页位置。

确认后 SHALL 返回工具 id 列表（而非显示名），顺序 SHALL 与注册表顺序一致，且 SHALL 去重。一项都未勾选时确认 SHALL 返回空列表，语义等价于 `--tools none`。

#### Scenario: 方向键与空格完成多选
- **WHEN** 用户在选择器中用方向键移动并用空格勾选两个工具后回车
- **THEN** 返回这两个工具的 id 列表，且不包含未勾选的工具

#### Scenario: 输入字符过滤候选项
- **WHEN** 用户在选择器中输入若干字符
- **THEN** 候选列表只保留显示名匹配该输入的项，导航与勾选在过滤后的列表上生效

#### Scenario: 一项未勾选时确认
- **WHEN** 用户不勾选任何项直接回车
- **THEN** 返回空列表，`init` 不为任何工具写入脚手架文件，其余初始化行为不受影响

#### Scenario: 提示行与可用计数
- **WHEN** 选择器渲染
- **THEN** 界面中包含可用工具总数，以及导航/勾选/确认三类键位的说明

#### Scenario: 候选项超过一屏时分页
- **WHEN** 注册表中的工具数量超过选择器单屏可显示的行数
- **THEN** 候选项分页呈现，界面指示当前页位置，且导航可跨页移动

### Requirement: 候选项呈现工具显示名与配置状态
每个候选项 SHALL 以工具的人类可读显示名呈现（如 `Claude Code`），SHALL NOT 只显示内部 id。候选项 SHALL 同时标注该工具在目标项目根目录下的当前状态，沿用既有判定：已存在 skill 文件标注为已配置；未配置但探测到其目录标注为已探测；两者都不满足则无标注。

#### Scenario: 候选项显示显示名
- **WHEN** 选择器列出候选工具
- **THEN** 每项呈现的是显示名（如 `Claude Code`、`Gemini CLI`），而不是 `claude`、`gemini` 这类 id

#### Scenario: 已配置工具带状态标注
- **WHEN** 某工具在目标项目根目录下已存在 skill 文件
- **THEN** 该候选项带有「已配置」标注，用于告知用户勾选它意味着覆盖重写

#### Scenario: 探测到目录但未配置的工具带标注
- **WHEN** 某工具的目录存在但其中没有 skill 文件
- **THEN** 该候选项带有「已探测」标注

### Requirement: 首次 setup 时预选探测到的工具
当目标项目根目录下**尚无任何**工具被配置过（即首次 setup）时，选择器 SHALL 把所有探测到目录的工具预先置为勾选状态，并 SHALL 在选择器上方明确告知哪些工具是因探测而被预选的。当已有任意工具被配置过时，SHALL 改为预选**已配置**的工具，使重复运行 `init` 的默认动作是刷新既有配置而不是扩大配置范围。

预选 SHALL 只是初始状态，用户 SHALL 能用空格取消任何预选项。

#### Scenario: 首次 setup 预选探测到的工具
- **WHEN** 项目根目录下存在 `.claude/` 但没有任何 loopspec skill 文件，用户交互式执行 `init`
- **THEN** 选择器中 Claude Code 初始为勾选状态，且界面告知它是因探测到目录而被预选

#### Scenario: 已配置过时预选已配置的工具
- **WHEN** 项目此前已为某些工具生成过 skill 文件，用户再次交互式执行 `init`
- **THEN** 选择器中初始勾选的是这些已配置的工具

#### Scenario: 预选项可被取消
- **WHEN** 用户对一个预选项按空格后回车
- **THEN** 返回结果中不包含该工具

#### Scenario: 无探测无配置时不预选
- **WHEN** 项目根目录下既没有任何工具目录也没有任何 skill 文件
- **THEN** 选择器中没有任何项处于勾选状态

### Requirement: 无法交互时的降级路径
选择器 SHALL 只在可交互终端中启用。当前不处于可交互终端时，工具选择 SHALL 退回既有行为：直接按 `none` 处理（不写任何脚手架、不报错、不阻塞）。选择器所依赖的第三方交互库 SHALL NOT 在 `--json` 路径或非交互路径上被导入或调用到需要终端的代码路径，使这些环境下不会因缺少终端而抛错。

用户在选择器中中断（如 Ctrl+C）SHALL 被视为放弃本次工具配置：`init` SHALL NOT 写入任何脚手架文件，且 SHALL NOT 以异常堆栈结束。

#### Scenario: 非交互环境退回 none
- **WHEN** 在非交互环境下执行 `loopspec init`（不带 `--tools`）
- **THEN** 不启动选择器，等价于 `--tools none`，命令正常完成

#### Scenario: JSON 模式不触碰交互库
- **WHEN** 执行 `loopspec init --json`
- **THEN** 不进入任何需要终端的代码路径，stdout 仍是一份可整体解析的 JSON

#### Scenario: 用户中断选择
- **WHEN** 用户在选择器中按 Ctrl+C
- **THEN** 命令不写入任何脚手架文件，并以可读的说明结束而非抛出未捕获异常

### Requirement: 显式 --tools 时跳过选择器
`--tools` 已显式给定时（含 `all`/`none`）SHALL NOT 启动选择器，直接采用该参数解析出的工具列表。参数的解析规则、大小写不敏感与未知 id 报错行为 SHALL 保持不变。

#### Scenario: 显式 --tools 绕过选择器
- **WHEN** 在可交互终端执行 `loopspec init --tools claude,codex`
- **THEN** 不出现选择器，直接为这两个工具写入脚手架

#### Scenario: --tools 的既有解析规则不变
- **WHEN** 传入 `all`、`none`、混合大小写的 id 列表或未注册的 id
- **THEN** 解析结果与报错行为与引入选择器之前完全一致
