# Security Review: PASS

## Scope Reviewed

- `design.md`（第 2 轮）：D1–D12 与「安全面自查」小节，重点复核新增的 D11（输出侧路径收口）、扩展后的 D9（元数据降级）、D12（轮次收集自己实现）与收紧后的 D8（`--schemas` 改用 `KEBAB_RE`）。
- `tasks.md`（第 2 轮）：全部 9 个任务组，重点为组 1（输入侧校验）、组 2（输出侧收口，含 2.5 符号链接目录环）、3.2/3.3/3.5（轮次收集与元数据降级）、4.2（`--schemas` 校验）、4.6（未认领遍历）、5.7（只读断言）。
- 被复用的既有实现：`paths.is_safe_relative_path` / `resolve_within`、`outputs.resolve_outputs` 与 `_is_artifact_candidate`、`config.read_metadata`、`models.KEBAB_RE`、`presentation.Presenter`。
- 第 1 轮的两条阻塞项（见 `.attempts/round-001/security/fail.md`）逐条验证。

## Checks Performed

**第 1 轮阻塞项的复核** —— 两条均已实质解决，不是换个说法：

- **符号链接可让输出逃出 workflow home**：已由新增的 D11 解决，且修法与建议方向一致——收口落在**输出边界的单一判定点**（`_contained`），而不是在各调用点分别打补丁。D11 逐一列出三个路径入口（schema 产物、轮次文件、未认领文件）并要求全部接入，位置目录本身也走同一判定，因此放宽归档月份目录名格式（D2）不会放宽安全边界。判定明确要求在解析符号链接**之后**进行，正对第 1 轮的根因。逃出即「跳过 + warning」而非整体失败，与 D9 的降级风格一致。特别确认了 D11 要求 warning 文本只含相对 change 目录的名字——避免了「修复本身又把 home 外路径打印出来」这个二阶问题。design 的输出面声明已改写为与机制相符的表述，tasks 2.1–2.4 有对应实现与测试，2.4 末尾还断言了全部 warning 文本中不出现 home 外的路径片段。
- **`_meta.yaml` 损坏导致未捕获异常**：已由扩展后的 D9 与新增的 D12 解决。D9 现在覆盖**每一份**元数据，且把「顶层不是映射」这一具体触发条件写进了要求（这正是 `AttributeError` 的来源），并明确「绝不抛非 `LoopspecError` 异常」。D12 说明了为什么加固点放在 `artifacts.py` 而不是 `attempts.list_rounds`——后者被 `history` 与 `instructions.priorAttempts` 复用，改它会连带改动两条已发布的响应契约；这个取舍合理，且顺带解决了 `list_rounds` 会吞掉无 `_meta.yaml` 轮次目录（即丢文件）的问题。tasks 3.3 与 3.5 覆盖五种降级情况。

**本轮完整检查**：

- **路径遍历**：输入侧两个校验点齐全——change 名过 `is_safe_relative_path`（D8.1），`--schemas` 每段过 `KEBAB_RE`（D8.2）。采纳了第 1 轮的非阻塞建议：`KEBAB_RE` 比「安全相对路径」更严，同时排除 `../../etc`、绝对路径与 `a/b`，且与 `ConfigSchemaRef.name` 的既有约束是同一条规则，不引入第二套命名标准。输出侧由 D11 收口。此项通过。
- **不受信输入的反序列化**：两份元数据均经 `yaml.safe_load`（无任意对象构造），缺失 / 非法 YAML / 顶层非映射三种情况全部降级（D9）。此项通过。
- **资源耗尽**：新审视了 D6/D11 的全目录遍历在符号链接目录环下是否会无限递归。标准库的 `glob`/`rglob` 对 `**` 不跟随目录符号链接，因此不成环；tasks 2.5 把这份依赖钉成回归断言，而不是留作口头假设——这一点是本轮新增要求。遍历规模本身受归档月份数与文档级目录规模限制。此项通过。
- **注入**：无外部命令执行、无 SQL/模板/LDAP/XPath；终端输出经 `Presenter` 转义（D7），控制字符改写为可见形式，tasks 6.4 有对应断言。此项通过。
- **密钥与敏感数据**：命令只输出路径、从不读取产物内容，`--json` 载荷中无凭据类字段。此项通过（但见 Notes）。
- **authn/authz**：不涉及，纯本地文件系统读取，权限由操作系统决定。此项通过。
- **写入面**：D3 刻意绕开 `_load_change_context` 的 `artifact_dir.mkdir`；tasks 5.7 用前后目录快照对比断言只读，并要求对**归档位置**也跑一遍。后者尤其重要——若沿用既有 helper，查询一个已归档的 change 会在归档目录里创建目录。此项通过。
- **第三方依赖**：无新增依赖，全部复用仓库内既有模块。此项通过。

## Notes

以下均为非阻塞，记录以便后续跟进：

- **`attempts.list_rounds` 自身的健壮性缺陷仍在**。`history` 与 `instructions.priorAttempts` 遇到损坏的 `_meta.yaml` 仍会以 traceback 终止。D12 有意不在本变更内改动它（它被两条已发布契约共用），并已记入 `design.md` 的 Open Questions。这是本变更**范围外的既有缺陷**，不构成本次的阻塞项，但应作为独立变更跟进。
- **未认领文件清单会打印 change 目录内任意文件的名字**，包括有人误放进去的 `.env` 之类。本命令从不读取文件内容，因此不泄露凭据本身；但路径名本身会出现在输出里。这是 D6 完整性目标的必然结果（任何隐式过滤都会在「所有产物路径」的承诺上开洞），接受该残余风险。
- **符号链接指向 home 外的产物会被静默排除在清单之外**（只在 `warnings` 中指名）。对正常用法无影响，但如果有人刻意用符号链接把大文件放在 home 外再从 change 目录引用，该产物不会出现在清单里。design 已把这一点列入 Risks，文档任务 8.3 要求对用户明示。
- **归属随 schema 定义漂移**是 D1 的已知代价，由 D6 的未认领兜底使文件不会消失。非安全问题，但文档任务 8.3 已要求明示，避免使用者把归属误读为历史事实。
