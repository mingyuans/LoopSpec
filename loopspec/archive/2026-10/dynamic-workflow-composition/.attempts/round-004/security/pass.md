## 已执行检查

- 严格 YAML 模型、重复键拒绝、有界读取和目录约束覆盖定义、请求、资源、报告与计划；文件打开和暂存写入也校验身份，处理路径替换。
- 计划摘要包含有效图、恢复规则、项目约束、基线、选择理由和全部落盘资源哈希；批准与落盘使用同一个缓存资源包，原资源替换阻断项仍已解决。
- Fragment 使用独立实例身份、产物和证据，FE/BE 的 PR Review 不互相覆盖；恢复边与依赖 DAG 分开，目标只能来自固化枚举。
- Gate begin/record 绑定审查开始输入并在记录前复核，检查就绪、轮次和单次令牌；失效证据使 Gate 重新就绪，旧报告不能作为当前 PASS。
- 项目最低保障不依赖 Agent 选择哪份 Profile；未知路径、缺失能力、过期证据和不支持输入默认失败。
- 最终 Assurance 是确定性校验 Gate，依赖所有代码交付分支；手写 pass.md 不能通过系统检查。
- 固定 Git 基线与工作树/Index 清单覆盖新增、删除、重命名、类型和模式变化；安全参数调用禁用外部驱动，路径不进入可执行 Shell。
- 精确管理目录和完整性校验避免证据自引用；业务代码、Profile/Fragment/规则源和可执行配置不能通过宽泛排除隐藏。
- 返工与修订受写锁和可恢复事务保护；新图不能与旧完成证据混合暴露，新修订默认不继承旧代码 Gate PASS。
- 设计不增加运行时依赖、外部服务、Secret 输出、身份伪装或自动业务代码回退。
