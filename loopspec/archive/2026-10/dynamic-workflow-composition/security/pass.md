## 已执行检查

- Fragment 只用 nodes；直接执行定义与 use 引用互斥，未知字段和独立 includes 被拒绝，避免双重编排与静默覆盖来源。
- 引用节点成员树、叶子身份、候选失败处理链和限额由编译器校验并随 Plan 固化；报告不能指定目标、归属或处理者。
- 引用 done 需要全部成员及必要证据有效，不仅检查某个终端报告；引用不是独立 Gate 证据来源，不能拿汇总状态代替真实测试或审查。
- 普通未完成和过期证据不伪造 FAIL；结果冲突、无效报告、读取失败、非法分类与未恢复事务阻塞，不进入业务恢复兜底。
- 最近内部恢复优先，预算耗尽后才向外传播；同一 FAIL 只绑定一个处理者和事务，多 Gate 失败串行处理，避免重复归档或同时重置。
- 各层 max_retries 及引用共享预算保留历史；父重置、删除报告和修订重命名不能清零。外层返工不会免除内部必要 Gate 的当前有效 PASS。
- reset 仅指向所属 Fragment 的上游节点；引用目标及选中引用边界展开全部成员，闭包包含失败来源和下游，不回退业务代码。
- 路径约束、打开时身份验证、严格 YAML、重复键拒绝、有界单次缓存与摘要绑定保持不变；图、归属、恢复顺序、资源字节及规则均进入有效摘要。
- 审批和落盘仍消费同一解析资源包，既往资源替换问题未因本轮修改重新引入。
- Gate begin/record、固定基线 Diff、系统 Assurance、精确控制目录、项目最低约束、原子激活和可恢复事务保留；旧 PASS 或轻量模板不能自动免除实际改动的审查。
- Git 使用安全参数数组而非 Shell，不运行外部 Diff 驱动或工作区脚本；没有新增第三方依赖、Secret 输出或认证绕过。
- V1 明确拒绝尚不支持的引用 on_fail、分类恢复及系统保障能力，不能忽略声明后激活计划。
