# 用 CLI 约束 agent 必须执行的步骤

适用时机：设计需要 agent 在命令之间完成某个人工步骤（审阅、整理、确认）的 CLI 流程时。

- 不要只把步骤写在 skill 里：模型可以直接调用 CLI 跳过。把步骤做进命令协议：第一段做检查并发凭据（绑定当时状态的摘要），同时返回该步骤的指引与要读的素材；第二段凭凭据完成，并要求显式填写结论与说明。原因：两次归档在只有 skill 约束时都跳过了 memory 审阅。来源：archive-memory-review（2026-11-19，用户提出两段式，设计经 Codex 审阅）。
- 结论要对照可观察的效果核对（例如选择 `updated` 时 memory topic 必须有变化，`none` 时必须没有），并把结论与说明写进可评审的记录（`state.md`）。在模型拥有同样文件权限的环境里，凭据和签名都不是安全边界，目标是让跳过变得显式、可核查、可追溯，而不是不可能。来源：同上；单测覆盖拒绝路径，LLM E2E 中真实模型两个归档场景都按两段执行并如实选择（`.llm-e2e-runs/20261119T154013Z/`）。
- 第二段要在提交点重新核对一切（锁内复核状态与摘要），批量操作把进度写回凭据，让失败后可以用同一凭据续跑。来源：同上，Codex 设计评审修订。
